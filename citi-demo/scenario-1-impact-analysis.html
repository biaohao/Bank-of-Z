Summary of Findings

Scope: Adding CUSTOMER-EMAIL PIC X(100) touches 31 files across 7 architectural layers — 5 copybooks, 13 CICS COBOL programs, 3 IMS COBOL programs, 2 BMS screens, 1 Db2 DDL file, 5 z/OS Connect YAML files, and 1 batch JCL for review.
The change starts in the copybooks, not the programs. Five shared copybooks (CUSTOMER.cpy, CUSTDB2.cpy, CRECUST.cpy, UPDCUST.cpy, INQCUSTZ.cpy) must be updated first. Every COBOL program inherits the new field automatically via COPY, but the 100-byte record length increase means all consumers must be recompiled — even those that never touch the email field.
The non-obvious risk — the 5 credit agency programs: CRDTAGY1.cbl through CRDTAGY5.cbl each COPY CUSTOMER.cpy but only read the credit score fields. They never use email. A keyword search for "email" would never find them. Yet they must all be recompiled, because the copybook record length has changed. A stale load module operating against an updated copybook produces a COMMAREA length mismatch at runtime — one that surfaces only when an async credit check fires during customer creation.
The Db2 host variable alignment rule: CUSTDB2.cpy declares Db2 host variables whose column order and length must exactly match the DDL in .setup/jcl/cics/Db2-create.jcl. Both must change together. Getting the order wrong causes a silent data corruption or a runtime SQL error that only appears in production.
The IMS path is separate: The IMS programs (IBGCUDAT.cbl, IBSCUDAT.cbl, LOADCUST.cbl) define their own customer segment structure inline — they do not share the CICS copybooks. They must be updated independently. The IMS phone field is PIC X(12), shorter than the CICS PIC X(20); a consistent email field size must be decided before implementation.
The z/OS Connect response mapping requires a manual step: The API schema JSON files auto-regenerate from the updated copybooks, but the response_200.yaml template mapping (which maps COMMAREA fields to JSON field names) is a separate file that must be edited by hand. It will not update itself.
Ordering matters: The Db2 schema change must be applied before any updated program is deployed. Copybooks must be updated before programs are compiled. BMS maps must be assembled before CUSTMAP.cpy is regenerated. The 23-step checklist at the bottom of this document captures the safe deployment order.
