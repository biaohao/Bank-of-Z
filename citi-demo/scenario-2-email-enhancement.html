Scenario

Add an email address field to the customer data model end-to-end: copybooks, COBOL programs, BMS screens, Db2 DDL, and z/OS Connect API mappings.

Summary

The field: CUSTOMER-EMAIL PIC X(100) in COBOL / CUSTOMER_EMAIL CHAR(100) in Db2. It slots in after the existing phone field at every layer, following the same positional pattern used by phone throughout all copybooks, programs, and DDL.
Dependency order is strict. Db2 DDL must be applied first. Copybooks must be updated before any COBOL program is compiled. BMS maps must be assembled before CUSTMAP.cpy is regenerated. z/OS Connect schemas regenerate automatically from the updated copybooks; only the five request/response mapping YAMLs need manual edits.
The HOST-CUSTOMER-ROW declaration must match CUSTDB2.cpy column order exactly. HV-CUSTOMER-EMAIL must appear between HV-CUSTOMER-PHONE and HV-CUSTOMER-ADDR-LINE1 in the working-storage host variable group in CRECUST.cbl, UPDCUST.cbl, INQCUST.cbl, and BANKDATA.cbl. A positional mismatch causes silent data corruption in Db2.
9 additional programs must be recompiled with no logic changes because CUSTOMER.cpy record length increases by 100 bytes: DELCUS, CREACC, INQACCCU, BNK1DCS, and CRDTAGY1–CRDTAGY5. DBB handles this automatically via dependency scanning.
IMS path: The IMS programs (IBGCUDAT, IBSCUDAT, LOADCUST) define their own inline customer segment — they do not share the CICS copybooks. Each needs its own EMAIL-CD / EMAIL-IN / EMAIL-OUT field added inline after the phone field.
